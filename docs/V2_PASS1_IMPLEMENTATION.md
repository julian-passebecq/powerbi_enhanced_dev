# Gen-2 Pass 1 — Semantic workbench and Report Studio

Start `PbiBench.exe`. Semantic View evolves the existing `DiagramView`, renderer and TE2 model session. Its Model mode retains active/inactive lines, cardinality, filter arrows, search, zoom, fit, group layout, neighborhood focus, relationship editing and native Undo. Dependencies exposes incoming/outgoing links from TE2's existing graph; double-click opens the existing object editor. Report Usage links local fields to pages/visuals and opens the selected visual in Report Studio. Issues combines current BPA evidence and broken local report references. Refresh PBIP/Git after external report edits.

DAX Workbench remains the everyday query surface: model navigation, existing editor/query tabs, results, problems, exact executed text, history, cancellation and semantic tests. Context/Help uses original local signatures and links to DAX Guide in the browser. Quick Open (`Ctrl+P` or `Ctrl+K`) routes model objects, query files, commands and the automation gallery to existing editors. The outer inspector is hidden in DAX because Context/Help occupies that role. DAX Studio retains the existing query-file/server/database handoff for deep performance analysis.

Apps / Tools detects/configures Bravo, Power BI Desktop, VS Code, Report Studio and the existing companions. It shows executable paths, detected versions and current applicability. Bravo requires live server/database IDs and receives only supported startup arguments. Desktop receives a known PBIP, otherwise a known PBIR; VS Code receives the project folder. Choose report context explicitly when a workspace contains multiple reports. Report Studio handoffs use contract version 1 and paths/page/visual IDs only.

Automate > Power BI C# Gallery contains 13 curated entries. Nine generate bounded typed recipes for SUM, COUNTROWS, explicit aggregations, format strings, display folders, summarization, hiding technical columns, name cleanup and descriptions. Four route to native measure-table creation, local DAX formatting, BPA and Explore/Profile. Cards expose selection requirements, parameters, risk, compatibility and provenance. Preview captures affected objects; apply uses the existing detached preview and native Undo. Generate C# shows exact source; Insert C# opens a new Safe editor document without replacing an existing draft or running code. Trusted execution retains its existing separate review/snapshot flow. User macros do not acquire verified-gallery status.

## Report Studio

`report-studio/PbiBench.ReportStudio.exe` is a separate .NET 10 WPF process. It references the pure `PbiBench.Pbir` and Core libraries, with no TE2, TOMWrapper, App, ModelEditor, Semantic or Fabric dependency. Open a `.pbip`, `definition.pbir`, report folder, or a root containing one report. For roots containing several reports, select one explicitly. The tree includes pages, visuals, bookmarks, filters, resources and report extension files. The wireframe displays bounds, position, title, type, z-order, hidden state and semantic fields; the inspector includes annotations, filters, schema/version and read-only JSON. It does not render Power BI visuals.

Actions / Changes supports page duplication, visual duplication, bounded cross-report visual copy, explicit field mapping, title edits, annotations, inventory export, validation and reviewed restore. Configure an action, preview every exact file, review the diff and hashes, then approve that immutable plan. Apply checks the complete captured report file set and any cross-report source snapshot, creates a durable backup, performs atomic replacement per file, validates the resulting report and records Git/disk status. A failure rolls back earlier files when they still match this transaction. An interrupted process leaves its durable backup for reviewed recovery. Restore previews original bytes and refuses later unrelated edits. No multi-file filesystem transaction is claimed.

Unknown properties are preserved. If they violate the pinned public schema, or the schema/version is unknown, writes are blocked. PBIR-Legacy is read-only; convert it using Desktop. Close the report in Desktop before editing its files. Linked filesystem paths, path escapes, duplicate JSON keys and oversized definitions are rejected. Definitions are bounded to 4 MiB per file / 64 MiB per report; project enumeration is bounded to 20,000 files. Local settings/cache and backup folders are excluded from indexing and exports. Inventory exports create a new file outside the report folder and cannot overwrite existing content.

Cross-report visual copy currently requires the same local model and a resource-independent report without custom visuals, report measures, groups or companion visual definitions. More complex transfers need a later explicit resource/field mapping workflow. Mapping changes structural Column/Measure references and recognized query labels, never arbitrary filter literals. Local report measures are distinguished from model measures. Unsupported aliases, missing remote models and partial TMDL declaration indexes are marked unverified; they are not declared broken. TMDL expression dependency evaluation is owned by Semantic IDE, not Report Studio.

## Verification and boundaries

Run targeted tests with the repository's .NET 10 SDK. `scripts/invoke-v2-gate.ps1` runs the final impacted Release build/tests, packages the apps with notices, checks process boundaries, and launches offline Report Studio and Semantic IDE smokes. Evidence is written under `artifacts/v2-gate-*`. Both smokes use synthetic local fixtures and capture screenshots. No live Bravo, Desktop, Fabric or XMLA session is asserted by offline checks.

The provided demo report under `examples/reportstudio-demo/` is a synthetic engineering fixture with a TMDL declaration excerpt, not a complete Desktop model. Hosted CI inspection and post-push audit belong to the separate reviewer. Cloud writes, report rendering, modern report C# hosting and broad gallery modeling templates remain outside this Pass 1 gate.
